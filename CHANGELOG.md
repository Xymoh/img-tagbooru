## [v1.3.7] - 2026-09-13

### Added

#### Terms of use, age gate and legal notices
- **`TERMS.md`** - terms of use, acceptable-use policy and privacy notice for the app. Covers the 18+ requirement, the prohibition on sexual content involving minors and on non-consensual intimate content of real people, third-party model licences, the "as is" disclaimer, and governing law (Poland).
- **First-launch acceptance dialog** - the app now asks the user to confirm they are at least 18 and to accept the terms before the main window loads. Acceptance is remembered in `~/.img_tagger/config.json` and re-requested when `TERMS_VERSION` changes. Declining exits.
- **`THIRD_PARTY_NOTICES.txt`** - licence texts for every package bundled in the executable (PySide6/Qt under LGPL-3.0, ONNX Runtime, NumPy, pandas, Pillow, huggingface_hub and the rest), plus attribution for the WD tagger models and the Danbooru tag vocabulary. Generated by `scripts/generate_third_party_notices.py`; bundled into the exe together with `TERMS.md` and `LICENSE`.
- **ℹ️ About button** in the status bar. The About dialog now states the licence, the no-telemetry privacy position, model attribution, and opens the terms, the third-party notices and the MIT licence in-app.

#### Content policy (`backend/content_policy.py`)
- **Minor age-descriptor tags are never emitted.** `loli`, `shota`, `toddlercon`, `child_on_child` are removed from every output path in every mode, including the ONNX image tagger. In Creative and Mature modes the wider set (`child`, `toddler`, `baby`, `aged_down`, `kindergarten_uniform`, …) is removed as well; Safe mode keeps the ordinary family-scene tags since it cannot produce suggestive output. Previously `loli`, `shota` and `child` passed through whenever the description mentioned them.
- **"All subjects are adults" rule** appended to every prompt that permits explicit output: description-to-tags, enrichment, the natural-language prose stage, the vision captioner's explicit priority, and the Wan video and MMAudio explicit rules.
- Adult content is otherwise untouched. Safe / Creative / Mature and the Explicit and Vulgar options behave exactly as before.

### Changed
- README: removed the Gemma 3 abliterated recommendation (Google's Gemma Prohibited Use Policy forbids sexually explicit output and circumventing its safety filters, so recommending it in this tool was recommending a terms violation); replaced "no content restrictions" wording; added a *Legal, privacy and attribution* section.
- `update.bat` now looks for `Img-Tagbooru.exe`, the asset name the CI workflow actually publishes (it looked for `img-tagger.exe`, so updates always failed). Links in the About dialog, help dialog and README now use the repository's current name, `Xymoh/img-tagbooru`.

## [v1.3.6] - 2026-09-09

### Added

#### Image → Natural-Language Prompt (vision model)
- **`📝 Write Prompt from Image`** in the Batch Tagger caption toolbar. A local vision-language model describes the image directly in prose, for Krea/Flux-style prompting. This bypasses the ONNX tagger entirely - one call, no tag vocabulary in between.
- **Why:** the WD taggers are Danbooru-trained, so on photographs they fail structurally, not marginally. On a real test photo the tagger returned 80 tags of which roughly a third were wrong or mutually contradictory - `painting (medium)` and `acrylic paint (medium)` on a photograph, six mutually exclusive garments (`dress` + `shirt` + `camisole` + `tank top` + …), `black hair` alongside `brown hair`, and `hatsune miku (cosplay)` projected onto a real person. Feeding that into the v1.3.5 prose stage yields a confident prompt describing the wrong image.
- **What tags cannot express:** booru tags have no vocabulary for lighting, camera framing, depth of field or scene character. On the same photo the vision model reported window light, the makeup brush on the desk, "bedroom or personal space", selfie framing, medium close-up, slight upward angle and soft focus - none of which are reachable by any threshold setting.
- **`backend/vlm_captioner.py`** - `VLMCaptioner` running through the same local Ollama instance as the description tagger (no new dependency, nothing leaves the machine). Accepts file paths, `Path`s, raw bytes or in-memory PIL images, so pasted/dropped images with no file on disk work too.
- **Model registry** - the four published JoyCaption beta-one quants (Q4_K_M 5.8 GB → Q8_0 9.42 GB), with install state shown per entry. JoyCaption is purpose-built for captioning images to prompt and train diffusion models, and is uncensored by design; stock VLMs refuse or sanitise a large share of this app's subject matter. Note the GGUF repo publishes **no `latest` tag**, so the quant is always named explicitly - a bare `ollama pull` of that repo 404s.
- **Caption styles and lengths** - Descriptive (formal/casual), Straightforward, Art critic, and Stable Diffusion prompt, at five lengths. The descriptive styles produce flowing prose, which is what natural-language image models condition on.
- **No tagging pass required** - the dialog captions loaded-but-untagged images, since the vision model does not need tags. Tagged results take precedence when present.
- **Batch captioning** with per-image progress, partial-failure tolerance (one bad image cannot sink the run), and cancel-on-close. Prompts save as `<name>_prompt.txt` so they never overwrite the `<name>.txt` tag captions used for LoRA training.
- **Caption instruction options** - the model's own verbatim option strings, exposed as checkboxes: lighting, camera angle, likely camera, SFW/suggestive/NSFW rating, skip-fixed-traits, vulgar slang, and keep-it-PG. Lighting and camera angle default on, since those are what natural-language image models condition on most.
- **🔞 Explicit toggle** - switches to a casual tone and appends the blunt-phrasing instruction. A formal register is what turns explicit imagery into "modest cleavage" - the model is not refusing, it is being polite. Mutually exclusive with keep-it-PG.

#### Image → Wan 2.2 Video Prompt
- **`backend/video_prompter.py`** - turns a first-frame description into an image-to-video prompt, in either a **second-by-second timeline** (`(At 0 seconds: …) (At 1 seconds: …) …`) or a **flowing paragraph**. Clip length is configurable (2-20s, default 5). The ceiling is a reliability bound on the timeline, not a Wan limit: past roughly 15s models begin dropping beats, so a near-complete timeline is accepted after the first retry rather than burning attempts on the last beat or two, and any shortfall is reported in the output instead of silently handing the video model fewer seconds than requested.
- **Deliberately a second stage, not a vision-model prompt.** JoyCaption is a captioner: asked to plan motion directly it restates the still - measured output included "hair remains mostly in place", "camera angle is the same" and "no significant changes", plus a hand-side contradiction against the image and a broken output format. Inventing plausible motion and holding an exact format is instruction-following, so it goes to the text LLM that already powers the description tagger. Stage 1 sees, stage 2 decides what happens next.
- **Anti-static prompt rules** - the system prompt forbids restating anything the first frame already fixes (clothing, hair, room, lighting) and bans "remains", "continues", "unchanged" and "no significant change" outright, since those were what the single-stage attempts filled every beat with. Motion is constrained to what is physically possible in one second.
- **Timeline is rebuilt from parsed beats, not scrubbed in place** - output is re-emitted from `(At N seconds: …)` matches, which normalises "1 second" to "1 seconds", recovers a missing final paren, collapses duplicated seconds, drops beats past the requested duration, and discards any reasoning the model leaked around them (qwen3 emitted a stray `</think>` and `\boxed{}` in testing). A short timeline is retried rather than shipped, since it would silently give the video model fewer seconds than asked for.
- Video prompts save as `<name>_video.txt`, so they collide with neither the `<name>_prompt.txt` image prompts nor the `<name>.txt` tag captions.

#### Vision-Model Detection
- **Vision-capable models are now auto-detected** rather than limited to the four curated JoyCaption quants. The picker queries Ollama for each installed model's capabilities and lists anything reporting `vision`, so a newer or more accurate captioner appears without a code change. Results are cached, since `/api/show` is a round trip per model.
- **Text-only models now fail with a clear message.** Selecting one previously produced a confusing error from deep in the call; it now states plainly that the model has no image input path. This matters because a strong text model can look like a natural choice here - `huihui_ai/mistral-small-abliterated:24b`, for instance, reports `completion, tools` with no `vision`, so it cannot caption images at all, only write the motion prompt from a caption another model produced.

#### Narration Hint
- **Free-text `Narration hint` field** in the image/video dialog steers how the description is worded - "cinematic film-noir tone", "clinical and factual", "emphasise texture and fabric". Folded into the caption request immediately after the base instruction rather than appended, since position drives register here; in video modes it also becomes a `NARRATION STYLE` block scoped so it shapes wording without overriding the output format or the one-second plausibility limit. Input is collapsed to one line, capped at 400 characters and auto-punctuated so a pasted paragraph cannot drown out the actual request.
- **Measured effect differs sharply by stage.** On the motion prompt (qwen3, a general instruction-follower) it is strong: "film-noir" produced "a quiet hesitation … a silent question to the silence"; "nature documentary" produced "as if the room itself is exhaling". On the image caption (JoyCaption) it is weak - "film-noir" only shifted the wording toward framing language with none of the mood - because JoyCaption is fine-tuned on a fixed instruction-template set, which is also why its own styles and options work so reliably. Documented rather than papered over, since the built-in options remain the effective lever for caption style.
- Not applied to the MMAudio stage, which has a strict two-line format and a 77-token budget.

#### MMAudio Prompts
- **`🔊 Also write an MMAudio prompt`** (on by default in video modes) writes the soundtrack for the same clip alongside the motion: a **positive** soundscape description and a **negative** prompt for exclusions, which is what MMAudio actually takes. Shown below the video prompt, with a `🔊 Copy Audio` button (Shift-click copies the negative instead).
- Built from both the motion *and* the first-frame description - the motion decides the event sounds, the still decides the room tone. Runs on the text model already resident from the video stage, so it costs a few seconds and no extra VRAM swap.
- **Non-audio terms are filtered out, not merely discouraged.** Asked for sound, models still emit camera language: a live run produced "soft focus shift" as a *sound*. Comma-separated items containing visual vocabulary (focus, camera, angle, lighting, framing, shot, zoom, blur…) are now dropped from the positive prompt.
- **The negative prompt can no longer mute what the positive asked for.** A live run excluded "ambient room sounds" and "camera sounds" while the positive asked for room tone. Items naming ambience, room tone, breathing, moaning, skin or rustling are stripped from the negative, which is also capped at six items.
- **Both audio prompts are trimmed to CLIP's 77-token window**, dropping whole comma-separated items so they never end mid-phrase. MMAudio encodes text with CLIP and silently discards anything past that limit, so a verbose soundscape would lose its tail with no error. Typical output is 21-39 tokens, so the guard rarely fires.
- **No per-second audio timeline, by design.** MMAudio pools text and video features into *global* conditioning via adaLN, so timestamps in the prompt collapse into a single vector and carry no temporal meaning; placement comes from Synchformer features sampled at 24fps off the video instead. A five-beat timeline would also exceed the 77-token text window on its own.
- Batch saves write audio to its own `<name>_audio.txt` rather than one blob, so a pipeline can consume the two separately.

### Fixed
- **Explicit options had no effect on video prompts.** `explicit` was never passed to the video stage at all - the worker called `build_from_caption(caption, style, duration)` with no such argument - so every video prompt was written in the second stage's own polite register regardless of what was ticked. On an explicit still this produced "she blinks slowly, lashes fluttering" where the motion is the entire point.
- **Explicit instructions were appended last, after they could take effect.** Register-setting options (blunt phrasing, vulgar slang) were emitted after the "include lighting / camera angle" detail requests, by which point the model had settled on a tone. They now come first. Measured on the same image: blunt-last gave "SFW but fucking suggestive", blunt-first gave "NSFW photograph … medium-sized tits".
- **Detail requests crowded out the subject.** With lighting, camera angle and content rating all requested, the model spent its word budget on those and never described what was actually exposed. Explicit mode now instructs it to cover the body, pose and state of dress first, and lighting/camera only afterwards - on a real NSFW image this took the caption from 74 words that omitted the chest to 95 that lead with it and still cover lighting and framing.
- **No system prompt was being sent.** The JoyCaption GGUF ships with `SYSTEM=None`, so the chat template injected an empty system message; the model's own `"You are a helpful image captioner."` is now supplied.
- **Image/video prompt dialog forgot its settings every time it closed.** Every control - vision model, caption style, length, option checkboxes, explicit, output mode, duration, stage-2 model, MMAudio toggle, narration hint - reverted to defaults on reopen, so working through a folder meant re-ticking the same boxes each time. Settings are now snapshotted on close and restored on open for the life of the app session, and deliberately kept nowhere more durable than that: a fresh launch starts from defaults. Combos restore by value rather than index, so a model installed between two opens (which shifts the list) still restores the right selection.
- **Video mode showed only a caption, with no error, when the motion stage failed.** Two bugs compounding. First, the stage-2 text-model dropdown listed JoyCaption - a vision captioner - and it could be selected for a language task it cannot do: asked for a timeline it restated the still on two runs in three and raised on the third. Second, that exception was caught per image and only ever surfaced if *every* image failed outright; with the caption succeeding, the video-stage failure was recorded and never shown, so the user saw a caption where a timeline should have been and reasonably concluded video mode was broken. Curated captioners are now excluded from the stage-2 list, the worker refuses one up front with a clear reason instead of burning three retries, per-stage failures ride along with results and raise a warning dialog, and a result that wanted a video but has none says `VIDEO PROMPT NOT GENERATED` in the output itself rather than presenting the bare caption.
- **Generated-prompt view was editable, and edits were silently discarded.** The image/video prompt dialog's output box accepted typing, but Copy and Save read from the result object rather than the widget - so an edited prompt copied out unedited, with nothing to indicate it. The view is now read-only (view and copy only), matching the Description Tagger's output. Both read-only views also had keyboard selection dropped as a side effect of `setReadOnly`, breaking the obvious Ctrl+A / Ctrl+C gesture; mouse *and* keyboard selection are now set explicitly.
- **Crash after several captions.** `DescriptionTagWorker`'s established pattern (wait for the OS thread, *then* drop the reference) was not followed by the new vision worker: `finished` is emitted from inside `run()` while the thread is still alive, so releasing the last Python reference there let Qt destroy a running `QThread` and abort the process. Compounding it, the worker and its slots lived in dialog-local closures, so signals still in flight after the dialog closed were delivered into destroyed widgets - which is why it took a few generations to surface. The worker is now held on the window, joined before release, and fully disconnected when the dialog closes; a still-running worker deliberately keeps its reference rather than being collected mid-flight.
- **No `closeEvent` on the main window** - nothing joined background threads at application exit, for any worker. Added one that cancels, disconnects and joins them.

### Changed
- README, Help dialog, and About dialog updated to document image-to-prompt captioning and to state plainly that the ONNX taggers are for anime/illustration, not photographs.

## [v1.3.5] - 2026-09-09

### Added

#### Natural-Language Prompt Output (Krea / Flux)
- **Output format selector** in the Description Tagger - a new **Output format** dropdown (`🏷️ Danbooru Tags` / `📝 Natural Language`) sits beside the existing input-mode toggle. The two axes are independent, so all four combinations work: description or seed tags in, tags or prose out. Seed tags → prose is the fast path for turning an existing booru caption into a Krea prompt.
- **Two-stage generation** - natural-language output runs the existing tag pipeline first (vocabulary grounding, relevance gate, concept expansion, backfill, semantic dedup, conflict resolution), then rewrites that cleaned tag set as one flowing paragraph. The prose therefore inherits every detail the tag pipeline *invents*: `a girl, emo, black hair` → 35 tags → a paragraph naming the studded belt, arm warmers and chipped nail polish the user never typed. The status bar reports `Stage 1/2` and `Stage 2/2`.
- **Prompt style tuned for T5-encoder models** - the prose system prompt front-loads the subject in the first clause (these models weight early tokens most heavily), then works outward through appearance → clothing → pose → setting → lighting → mood, and closes on framing, camera angle and style. It explicitly bans the SDXL-anime habits that are pure noise on these encoders: underscores, attention weights like `(detailed:1.3)`, and `masterpiece, best quality, highres, absurdres` spam.
- **Anti-contradiction rule** - the prose stage is forbidden from writing anything the tags contradict (barefoot against a `boots` tag, sunlight against a `night` tag), a failure mode observed in live testing.
- **Both artifacts from one run** - a `🏷️ Copy Source Tags` button appears after a prose run so the intermediate Danbooru tag set is still copyable; the primary copy button switches between prose and tags with the format.
- `DescriptionTagger.generate_natural_prompt()`, `NaturalPromptResult`, and prose-specific few-shot pools per creativity mode. `DescriptionTagWorker` gains an `output_format` flag plus `prompt_finished` and `stage` signals; passing the stage-1 result into stage 2 avoids regenerating tags.

### Fixed
- **Prose length overshoot** - the model routinely ignored the stated 70–110 word target (176/117/146 words observed). The instruction is now a hard limit, backed by a deterministic `_trim_to_word_budget()` that cuts back to a sentence boundary at 130 words. An over-long prompt dilutes the subject on these encoders.
- **Leaked reasoning in prose output** - qwen3 intermittently emitted its reasoning as *plain text* with no `<think>` tags, so neither the stop sequence nor the existing cleanup caught it (a `(With a focus on the initial request of…` preamble and a trailing `Okay, let's see. I need to convert the given tags…`). Cleanup now drops whole sentences matching reasoning markers, strips mid-sentence meta handoffs, and `_contains_meta_leak()` forces a regeneration rather than shipping a leaked attempt.

### Changed
- **Startup splash screen** - the window takes a moment to build (several tabs, plus probing Ollama for installed models), during which the app previously showed nothing at all. A splash now reports real progress: *Building interface → Loading tag vocabulary → Checking for local models → Finishing up → Ready*. It is painted at runtime rather than shipped as an asset, so it survives PyInstaller builds with no extra `--add-data` wiring, and renders at 2x for HiDPI.
- **Caption toolbar split into two rows.** Eight buttons need ~1230px of natural width while the caption pane is ~940px at the default window size, so the single row could only fit by eliding labels - "Save Beside Source" rendered as "Save Beside Sour". Row 1 is now caption/prompt actions, row 2 is save/export/analysis; both fit even at the minimum window width. Labels were shortened too (full wording remains in the tooltips), and each button is pinned to its natural width so elision is impossible. The pinning is deferred to the first event-loop turn because a button's size hint is not final during construction - not even after `ensurePolished()` - and reading it early under-sizes the minimum by just enough to clip a trailing character.
- **`APP_VERSION` constant** replaces three hardcoded copies of the version string across the title bar, About dialog and `QApplication` metadata.
- **Description Tagger layout** - the input-mode toggle and the new output-format selector share one two-column row instead of stacking into separate group boxes, keeping the left config column short enough for a 1920×1080 screen.
- Prose output renders in the UI font rather than the green monospace used for tag lists.
- README, Help dialog, and About dialog updated to describe natural-language prompt output.

## [v1.3.2] - 2026-05-15

### Added

#### Description Tagger - Structured Category Prompting
- **Structured category checklist** in the system prompt forces the LLM to cover every visual dimension: `[PARTICIPANTS]` `[HAIR]` `[EYES]` `[CLOTHING]` `[ACCESSORIES]` `[BODY]` `[POSE]` `[EXPRESSION]` `[SETTING]` `[LIGHTING]` `[ATMOSPHERE]` `[FRAMING]` `[QUALITY]`. Creative/Mature also get `[NSFW]`. This is the single biggest quality improvement - output now matches real Danbooru post density (30-50+ tags).
- **Danbooru-density few-shot examples** - all three mode pools replaced with 30-45 tag examples that demonstrate the specificity level expected (e.g. `black_shirt, t-shirt, long_sleeves, miniskirt, pleated_skirt, boots, black_boots, knee_boots, arm_warmers, black_arm_warmers, nail_polish, x_hair_ornament, hair_over_one_eye, twintails, sidelocks, red_background`).
- **Archetype-specific clothing backfill pools** - when the LLM under-delivers, the backfill now pulls from archetype-specific clothing/accessory lists: emo/goth → `black_shirt, arm_warmers, knee_boots, studded_belt`; school → `serafuku, kneehighs, loafers, hair_ribbon`; elf/archer → `bow_(weapon), quiver, cape, leather, gauntlets`; bikini/beach → `barefoot, sand, side-tie_bikini_bottom, tan`.
- **Expanded concept expansion map** - 30+ new entries covering subcultures (`emo`, `goth`, `punk`), relationships (`couple`, `lovers`, `romantic`), outdoor settings (`lake`, `river`, `ocean`, `sea`, `mountain`, `field`, `meadow`, `garden`, `rooftop`, `city`, `street`), weather/time (`rain`, `snow`, `sunset`, `night`, `winter`, `summer`, `spring`, `autumn`), and activities (`swimming`, `swimsuit`, `bikini`, `festival`, `wedding`).
- **Expanded literal tag map** - 25+ new phrase→tag mappings: `bikini`, `swimsuit`, `one-piece`, `school uniform`, `emo`, `goth`, `punk`, and all major settings (`lake`, `river`, `ocean`, `beach`, `forest`, `park`, `bedroom`, `kitchen`, `library`, `classroom`, `rooftop`, `alley`, `cathedral`, `church`).
- **Mature wildcard injection** (`_inject_mature_wildcards`) - on SFW descriptions in Mature mode, injects 2-3 tasteful suggestive tags from scene-aware pools (lake → `wet, wet_hair, bare_shoulders`; forest → `thighs, messy_hair`; bedroom → `bare_shoulders, dim_lighting`; generic → `cleavage, bedroom_eyes, parted_lips`).
- **Expanded universal tag set** - added hair styles (`ponytail, twintails, braid, bangs, messy_hair, wavy_hair`), skin/body details (`thighs, legs, bare_shoulders, collarbone, navel, midriff, cleavage, wet, wet_hair, sweat`), accessories (`choker, necklace, earrings, ring, bracelet, ribbon, piercing`), and atmosphere (`golden_hour, ambient_light, scenery, cinematic_lighting`).

#### Tag Enrichment
- **Tag Enrichment mode** - paste seed tags like `1girl, witch_hat, forest, broom, night` and the AI expands them into a full 30-50 tag set with complementary clothing, atmosphere, lighting, and detail tags.
- Input mode toggle (`📝 From Description` / `🏷️ From Seed Tags`) in the Description Tagger tab.
- Three enrichment few-shot example sets (safe, creative, mature) with Danbooru-density outputs.
- `DescriptionTagWorker` `enrich_mode` flag routes to `tagger.enrich_tags()`.

#### Infrastructure
- **Comprehensive README** - complete rewrite covering all features, Description Tagger deep-dive with example output, mode comparison table, writing tips, full post-processing pipeline explanation, model recommendations with tested benchmarks, project structure, FastAPI docs, and training tips.
- **`start-ui.bat` fallback chain** - fixes silent failure when `.venv` is not at the project root. Now tries: (1) `.venv\Scripts\pythonw.exe`, (2) `pythonw` on PATH, (3) `python` on PATH, (4) clear error message with fix instructions. Works with conda, system Python, and differently-named venvs.

### Changed

#### Description Tagger
- **Mode-specific framing** in system prompt: Safe = "stay literal", Creative = "TURN THE DESCRIPTION INTO A RICH, IMAGE-READY PROMPT - be generous", Mature = "expand like Creative AND add suggestive flair".
- **Target tag counts raised**: Safe 35, Creative 50, Mature 50 (was 18/30/35). `num_predict` budgets raised to 500/700/800 tokens.
- **`min_accept` now checks LLM-produced tags** (before backfill) - prevents sparse LLM output padded by backfill from passing the retry threshold. Retries now actually fire when the model under-delivers.
- **Backfill fill ratio** raised to 80% of target for Creative/Mature (was 75%).
- **Safe mode gate** - all modes now use `min_score >= 1` (universal atmosphere tags pass). Safe mode's SFW guarantee is enforced by a dedicated suggestive-tag blocklist (`cleavage, navel, thighs, bare_shoulders, seductive_smile, bedroom_eyes`, etc.) rather than a stricter gate score.
- **`MAX_TAGS`** raised from 50 to 60.
- Generation temperatures adjusted: Creative 0.75 (was 0.65), Mature 0.90 (was 1.05 - was too high, causing incoherence).
- Enrichment mode temperatures: Mature 0.90 (was 1.05).

### Fixed
- Creative mode was producing the same sparse output as Safe because the system prompt said "Only add tags DIRECTLY implied" and "Limit output to the natural number of tags" - both instructions removed.
- `fox_ears`/`fox_tail` hallucination on unrelated prompts reduced - animal-feature tags now require archetype support in the description.
- NSFW few-shot example (`"a nun giving a blowjob"`) was leaking into the Creative pool for SFW inputs - Creative pool now contains only SFW examples.
- Backfill was satisfying `min_accept` before the LLM had a chance to retry with richer output - fixed by checking raw LLM tag count, not post-backfill count.

## [Unreleased]

### Added
- **Relevance gate** in Description Tagger post-processing. Every tag is scored 0-3 against the user's description; score-0 tags (likely hallucinations) are dropped. Franchise tags like `magic_knight_rayearth`, `library_of_ruina`, `master_sword` no longer leak into unrelated prompts.
- **Concept expansion map** (`_CONCEPT_EXPANSIONS`) - 30+ archetype keywords (nun, witch, knight, maid, catgirl, orc, succubus, kitchen, cathedral, library, ...) map to plausible Danbooru tags, letting the LLM use e.g. `veil` for a nun description without that word being named.
- **NSFW act expansion map** (`_ACT_EXPANSIONS`) - 57 sex-act keywords expand to anatomy/position/reaction tags (e.g. `blowjob` → `fellatio, penis, open_mouth, saliva, kneeling, tongue_out`). Applied only in creative/mature modes; safe mode never sees anatomy.
- **Mutual-exclusion conflict resolver** - keeps only the highest-post_count tag within pose/viewpoint/framing/mouth/time-of-day groups (no more `standing + kneeling + lying` collisions).
- **Repetition-loop detector** in `_parse_tags` - truncates the raw response when the model stutters into `saliva, saliva, saliva, ...` loops.
- **Disambiguator auto-block** - tags shaped `tag_(context)` are dropped unless the parenthetical matches a word in the description.
- **Concept-expansion rescue path** - when the LLM returns nothing usable, synthesize tags from archetype and act expansions so the output is never empty.
- **Per-mode retry acceptance thresholds** - safe accepts ≥3 tags, creative ≥5, mature ≥6. Up to 3 attempts with +0.15 temperature per retry. Best result across attempts is kept.
- Expanded `_extract_literal_tags_from_description` from 15 phrases to 80+ (anatomy, body type, sex acts, participants, fluids, archetypes).

### Changed
- **Qwen3 `/no_think` directive** replaces the old `<think>` prefill. Generation time dropped from ~11s to ~4s per run (65% faster) because the reasoning block no longer consumes the `num_predict` budget.
